# ShopCraft - 기능 상세 명세

## 1. 화면별 기능 매핑

### 1.1 랜딩 페이지 (`/`)

| 영역 | 기능 | 상세 |
|------|------|------|
| 히어로 섹션 | 서비스 소개 | 캐치프레이즈, CTA 버튼 ("상품 둘러보기", "판매 시작하기") |
| 인기 상품 | 상품 카드 목록 | `sales_count` 기준 상위 8개, 가격/평점/판매수 표시 |
| 카테고리 | 카테고리 바로가기 | 아이콘 + 이름, 클릭 시 `/products?category={slug}`로 이동 |
| 최신 상품 | 신규 등록 상품 | `created_at` 기준 최신 8개 |

### 1.2 로그인 페이지 (`/login`)

| 영역 | 기능 | 상세 |
|------|------|------|
| 이메일 로그인 | 폼 입력 | 이메일, 비밀번호 입력 필드 |
| 유효성 검사 | 실시간 검증 | 이메일 형식, 비밀번호 빈값 체크 |
| Google 로그인 | OAuth 버튼 | "Google로 로그인" 버튼, Supabase OAuth 호출 |
| 비밀번호 찾기 | 링크 | "비밀번호를 잊으셨나요?" → 재설정 모달/페이지 |
| 회원가입 이동 | 링크 | "아직 계정이 없으신가요? 회원가입" |
| 에러 처리 | 에러 메시지 | 로그인 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다." |

### 1.3 회원가입 페이지 (`/signup`)

| 영역 | 기능 | 상세 |
|------|------|------|
| 이메일 가입 | 폼 입력 | 이메일, 비밀번호, 비밀번호 확인, 닉네임 |
| 유효성 검사 | 실시간 검증 | 이메일 형식, 비밀번호 규칙(8자+영문+숫자+특수문자), 비밀번호 일치, 닉네임 2~50자 |
| Google 가입 | OAuth 버튼 | "Google로 시작하기" |
| 이메일 인증 안내 | 성공 화면 | 가입 완료 후 "인증 이메일을 발송했습니다. 이메일을 확인해주세요." |
| 로그인 이동 | 링크 | "이미 계정이 있으신가요? 로그인" |

### 1.4 상품 목록 페이지 (`/products`)

| 영역 | 기능 | 상세 |
|------|------|------|
| 검색바 | 텍스트 검색 | 제목/설명 기반 검색, 디바운스 300ms |
| 카테고리 필터 | 사이드바/탭 | 카테고리별 필터링 |
| 가격 필터 | 범위 슬라이더 | 최소/최대 가격 설정 |
| 정렬 | 드롭다운 | 최신순, 인기순, 가격 낮은순, 가격 높은순, 평점순 |
| 상품 카드 | 그리드 표시 | 썸네일, 제목, 가격, 평점, 판매수, 판매자명 |
| 페이지네이션 | 하단 | 페이지 번호 또는 무한 스크롤 |
| 빈 상태 | 안내 메시지 | 검색 결과 없을 때 "검색 결과가 없습니다." |

### 1.5 상품 상세 페이지 (`/products/:id`)

| 영역 | 기능 | 상세 |
|------|------|------|
| 이미지 갤러리 | 슬라이더 | 상품 이미지 좌우 슬라이드, 썸네일 목록 |
| 상품 정보 | 텍스트 표시 | 제목, 설명(마크다운), 가격, 카테고리 |
| 파일 정보 | 메타데이터 | 파일명, 파일 크기 (다운로드 URL은 비노출) |
| 판매자 정보 | 카드 | 판매자명, 아바타, 소개, 등록 상품 수 |
| 구매 버튼 | CTA | "₩5,900 구매하기" → 주문 생성 → Stripe Checkout |
| 이미 구매한 경우 | 상태 변경 | 구매 버튼 대신 "다운로드" 버튼 표시 |
| 리뷰 섹션 | 목록 | 평균 평점, 별점 분포, 리뷰 목록 (페이지네이션) |
| 리뷰 작성 | 폼 | 별점 선택 + 텍스트 입력 (구매자만 표시) |

## 2. 기능별 상세 동작 정의

### 2.1 회원가입 프로세스

```
1. 사용자가 이메일/비밀번호/닉네임 입력
2. 클라이언트 유효성 검사
   - 이메일: 형식 검증 (RFC 5322)
   - 비밀번호: 8자 이상, 영문+숫자+특수문자
   - 닉네임: 2~50자
3. POST /api/auth/signup 호출
4. 서버: Supabase Auth에 사용자 생성
5. 서버: profiles 테이블에 레코드 생성
6. Supabase: 인증 이메일 발송
7. 클라이언트: "이메일을 확인해주세요" 안내 표시
8. 사용자가 이메일 링크 클릭 → 인증 완료
9. 로그인 페이지로 리다이렉트
```

### 2.2 Google OAuth 프로세스

```
1. "Google로 로그인" 버튼 클릭
2. Supabase Auth의 OAuth URL로 리다이렉트
3. Google 로그인 화면에서 인증
4. /api/auth/callback으로 리다이렉트
5. 서버: code를 세션 토큰으로 교환
6. 서버: 신규 사용자면 profiles 레코드 자동 생성
   - nickname: Google 프로필의 이름 사용
   - avatar_url: Google 프로필 사진 URL
   - email: Google 계정 이메일
7. 메인 페이지로 리다이렉트
```

### 2.3 상품 등록 프로세스

```
1. 판매자가 /products/new 접속
2. 상품 기본 정보 입력 (제목, 설명, 가격, 카테고리)
3. 이미지 업로드 (최대 5장)
   - 드래그앤드롭 또는 파일 선택
   - 업로드 즉시 Supabase Storage에 저장
   - POST /api/products/:id/images
4. 판매 파일 업로드 (최대 50MB)
   - POST /api/products/:id/files
   - private 버킷에 저장
5. 임시저장(draft) 또는 발행(active) 선택
6. POST /api/products 호출
7. 성공 시 상품 상세 페이지로 이동
```

### 2.4 구매/결제 프로세스

```
1. 상품 상세 페이지에서 "구매하기" 클릭
2. 로그인 확인 (미로그인 시 로그인 페이지로)
3. POST /api/orders 호출 → 주문 생성 (status: pending)
4. POST /api/stripe/checkout 호출 → Stripe Checkout 세션 생성
5. Stripe Checkout 페이지로 리다이렉트
6. 사용자가 카드 정보 입력 후 결제
7. 결제 성공 → /checkout/success로 리다이렉트
8. Stripe Webhook (checkout.session.completed) 수신
9. 서버 처리:
   a. orders.status → 'paid'
   b. payments.status → 'succeeded'
   c. products.sales_count += 1
10. 사용자가 주문 상세에서 다운로드 가능
```

### 2.5 파일 다운로드 프로세스

```
1. /orders/:id 에서 "다운로드" 버튼 클릭
2. GET /api/downloads/:orderItemId 호출
3. 서버 검증:
   a. 인증 확인
   b. 주문 소유자 확인
   c. 주문 상태 = 'paid' 확인
4. Supabase Storage에서 서명된 URL 생성 (유효시간 60분)
5. downloads 테이블에 기록 저장
6. 클라이언트에 서명된 URL 반환
7. 브라우저가 파일 다운로드 시작
```

### 2.6 리뷰 작성 프로세스

```
1. 상품 상세 페이지의 리뷰 섹션
2. 구매 이력 확인 → 구매자에게만 작성 폼 표시
3. 별점(1~5) 선택 + 코멘트 입력
4. POST /api/products/:id/reviews 호출
5. 서버 검증:
   a. 해당 상품 구매 이력 확인
   b. 기존 리뷰 존재 여부 확인 (1상품 1리뷰)
6. 리뷰 저장
7. products.average_rating 재계산:
   average_rating = (기존 합계 + 새 rating) / (review_count + 1)
8. products.review_count += 1
9. 리뷰 목록 새로고침
```

## 3. 에러 케이스 및 예외 처리

### 3.1 인증 관련

| 상황 | 처리 |
|------|------|
| 토큰 만료 | 자동 토큰 갱신 (refresh token), 실패 시 로그인 페이지 이동 |
| 비인가 접근 | 401 → 로그인 페이지로 리다이렉트 |
| 권한 부족 | 403 → "접근 권한이 없습니다." 토스트 메시지 |
| 이메일 미인증 | 로그인 시 "이메일 인증을 완료해주세요." 안내 |

### 3.2 상품 관련

| 상황 | 처리 |
|------|------|
| 삭제된 상품 접근 | 404 → "존재하지 않는 상품입니다." |
| 비활성 상품 구매 시도 | 400 → "현재 구매할 수 없는 상품입니다." |
| 본인 상품 구매 시도 | 400 → "본인의 상품은 구매할 수 없습니다." |
| 이미 구매한 상품 재구매 | 409 → "이미 구매한 상품입니다." |
| 이미지 업로드 실패 | 파일 형식/크기 에러 메시지, 재시도 안내 |
| 파일 업로드 실패 | 파일 크기 에러 메시지, 재시도 안내 |

### 3.3 결제 관련

| 상황 | 처리 |
|------|------|
| Stripe Checkout 취소 | /checkout/cancel로 리다이렉트, 주문 유지 (재시도 가능) |
| 결제 실패 (카드 거절 등) | Stripe가 에러 표시, 주문 상태 pending 유지 |
| Webhook 수신 실패 | Stripe가 자동 재시도 (최대 3일간) |
| Webhook 중복 수신 | 멱등성 처리 (payment_intent_id로 중복 체크) |
| 주문 금액 ≠ 결제 금액 | Webhook에서 금액 검증, 불일치 시 로그 기록 |

### 3.4 다운로드 관련

| 상황 | 처리 |
|------|------|
| 미결제 주문 다운로드 시도 | 403 → "결제가 완료되지 않았습니다." |
| 서명된 URL 만료 | 새 URL 재생성 (다운로드 버튼 재클릭) |
| 파일이 Storage에서 삭제됨 | 500 → "파일을 찾을 수 없습니다. 관리자에게 문의하세요." |

## 4. 상태 관리 전략

### 4.1 서버 상태 (Server State)

| 데이터 | 방식 | 설명 |
|--------|------|------|
| 사용자 인증 | Supabase Auth + React Context | 전역 인증 상태 관리 |
| 상품 목록 | `fetch` + URL 쿼리 파라미터 | 필터/정렬은 URL로 관리 (뒤로가기 지원) |
| 상품 상세 | Next.js SSR (`generateMetadata`) | SEO를 위한 서버 사이드 렌더링 |
| 주문/결제 | `fetch` | 클라이언트 요청 |

### 4.2 클라이언트 상태 (Client State)

| 데이터 | 방식 | 설명 |
|--------|------|------|
| 폼 입력값 | React `useState` | 각 폼 컴포넌트 로컬 상태 |
| 모달/토스트 | React Context | 전역 UI 상태 |
| 이미지 업로드 진행 | `useState` | 업로드 진행률 |
| 테마 (다크모드) | localStorage + Context | 사용자 테마 설정 (P2) |
